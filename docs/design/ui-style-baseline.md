# 当前 UI 风格基线

本文总结 ZhiCore 前端截至 2026-07 的实际落地 UI 风格，用于新增页面、页面优化和设计评审时对齐视觉方向。它记录“当前产品应该长什么样”，不替代 `css-style-guide.md` 的 CSS owner 和 token 规则。

## 风格定位

| 维度     | 当前结论                         | 设计含义                                                   |
| -------- | -------------------------------- | ---------------------------------------------------------- |
| 产品气质 | 深色、专注、工程化、内容优先     | 界面像知识工作台和内容社区，不做营销页式大面积装饰。       |
| 主色关系 | 深蓝黑底 + 青绿色强调            | 青绿色只用于焦点、主操作、当前态、品牌识别和少量高亮。     |
| 信息密度 | 中高密度，服务阅读、浏览、写作   | 页面应利于扫描和重复使用，避免无意义的巨型首屏和装饰卡片。 |
| 视觉层级 | 线、留白、字号、轻微背景差异优先 | 能用分隔线和排版解决的结构，不默认包进卡片。               |
| 动效     | 轻量、短促、功能性               | hover 可有轻微上浮或颜色变化，但不制造持续运动负担。       |

## 视觉 Token 现状

| 类型     | 当前主值                                                         | 使用规则                                                                        |
| -------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 页面背景 | `--color-bg: #0f151b`                                            | 全站默认深色背景，允许使用固定的青绿 / 蓝色径向微光。                           |
| 抬升背景 | `--color-bg-elevated: #161e25`、`--color-bg-elevated-2: #1e2933` | 用于侧栏、阅读操作栏、表单容器和需要稳定边界的面板。                            |
| 玻璃面   | `--color-panel`、`--color-panel-soft`、`--color-panel-glass`     | 用于首页推荐卡、登录页品牌容器、少数强调性模块；不作为所有 section 的默认外壳。 |
| 边框     | `--color-border`、`--color-border-strong`                        | 当前 UI 主要靠细边框建立层级；分隔线优先于重阴影。                              |
| 文字     | `--color-text-strong`、`--color-text`、`--color-text-soft`       | 标题、正文、辅助信息必须拉开层级；辅助信息不抢主内容。                          |
| 强调色   | `--color-primary: #00e5b5`                                       | 用于品牌 mark、当前导航、主按钮、focus ring、活跃态和关键入口。                 |
| 状态色   | `--color-warning`、`--color-danger`                              | 只表达状态，不用作页面装饰主色。                                                |

## 页面类型

| 页面类型        | 代表页面                 | 推荐结构                                             | 避免                                                  |
| --------------- | ------------------------ | ---------------------------------------------------- | ----------------------------------------------------- |
| 首页 / 品牌入口 | `/`、登录页              | 可使用品牌 hero、玻璃卡片、微光背景和更强视觉冲击。  | 把 demo 式假数据包装成生产事实。                      |
| 内容浏览页      | `/explore`、`/community` | 平铺 header、状态摘要、分类控件、分隔线内容列表。    | 把每个页面 section 都做成卡片；把发现页做成主页复刻。 |
| 阅读页          | `/posts/:postId`         | 三栏阅读：目录、正文、操作栏；正文保持长阅读节奏。   | 强装饰背景、过多卡片嵌套、把 unknown 计数显示成 `0`。 |
| 工具 / 编辑页   | `/editor`                | 工作台布局、稳定工具栏、明确状态反馈。               | 装饰性 hero、频繁动效、控件尺寸随内容跳动。           |
| 设置 / 用户页   | 后续 User 页面           | 任务型信息架构：资料摘要、表单、设置导航、状态提示。 | 营销式首屏、说明性文案覆盖真实任务。                  |

## 布局语言

| 元素          | 当前风格                                            | 后续约束                                                  |
| ------------- | --------------------------------------------------- | --------------------------------------------------------- |
| Header        | sticky 顶栏，品牌在左，导航中等密度，搜索与动作在右 | 顶栏保持工具感；新增导航入口要对应真实页面能力。          |
| 移动端导航    | 底部固定导航，中间写作按钮突出                      | 移动端优先保留核心入口，不把主要操作藏到横向滚动。        |
| 页面标题区    | 内容页使用平铺标题 + eyebrow + 简短说明             | 除首页外不默认做 hero 卡片。                              |
| 列表          | 内容列表多用分隔线、轻量 meta、标题、摘要、操作栏   | 文章和社区列表应可快速扫描，不堆叠厚卡片。                |
| 侧栏          | 只在信息确实辅助主任务时出现                        | 侧栏必须来自真实数据或明确降级，不能硬编码热度 / 成员数。 |
| 空态 / 错误态 | 虚线边框、简短说明、明确重试按钮                    | 错误不道歉，不把未知状态伪装成确定空数据。                |

## 组件质感

| 组件                 | 当前做法                            | 规则                                                      |
| -------------------- | ----------------------------------- | --------------------------------------------------------- |
| 主按钮               | 青绿实底、深色文字、轻微 hover 变亮 | 只给真正主动作使用，例如写作、重试、保存。                |
| 次按钮 / 图标按钮    | 透明或浅玻璃底，hover 变亮或转主色  | 图标按钮优先配 `aria-label`，不要用长文字挤压工具栏。     |
| Segmented / 分类控件 | pill 形、当前态反差明显             | 当前态必须由真实状态驱动，不写死 active class。           |
| 内容卡片             | 首页可玻璃卡；浏览页更偏平铺        | 新增重复内容项优先列表化，卡片只用于需要独立容器的 item。 |
| 标签 / badge         | 小字号、pill、低饱和边框            | 标签是分类信息，不承担大面积装饰。                        |
| Focus                | `2px` 青绿色 outline                | 所有可交互元素必须有可见键盘焦点。                        |

## 排版基线

ZhiCore 的产品页使用固定 `rem` 字号层级，不使用 viewport 驱动字号。通知、私信、设置、用户资料、搜索、资源列表等任务型页面优先引用 `src/style.css` 中的 `--font-size-ui-*` / `--font-weight-ui-*` / `--line-height-ui-*` token。

| 层级        | Token                          | 当前值      | 适用区域                               | 规则                                               |
| ----------- | ------------------------------ | ----------- | -------------------------------------- | -------------------------------------------------- |
| 品牌标题    | -                              | 按页面定义  | 首页、登录页、错误页等品牌表达区域     | 可略大，但不扩散到任务型页面。                     |
| 页面标题    | `--font-size-ui-page-title`    | `1.375rem`  | 通知、私信、设置、用户资料的页面标题   | 强文字色，中高字重，短句；不要做营销式巨型标题。   |
| 分区标题    | `--font-size-ui-section-title` | `1.125rem`  | 侧栏标题、表单分区标题、工具区标题     | 用于真实结构分区，不作为每个小块的装饰标题。       |
| 行标题      | `--font-size-ui-row-title`     | `0.9375rem` | 通知项标题、表单小标题、列表行主文本   | 标题应能独立扫描，行高保持紧凑。                   |
| 正文 / 控件 | `--font-size-ui-body`          | `0.875rem`  | 导航项、按钮、说明文字、列表摘要       | 产品 UI 默认正文层级；说明文字也不能低于可读下限。 |
| 辅助信息    | `--font-size-ui-meta`          | `0.8125rem` | 时间、计数说明、错误提示、字符计数     | 使用 soft 色并弱化，不抢主任务。                   |
| Caption     | `--font-size-ui-caption`       | `0.75rem`   | 极少量 eyebrow、短标签、密集辅助标识   | 谨慎使用；长句说明不得使用该层级。                 |
| 数据强调    | `--font-size-ui-data`          | `1.5rem`    | 未读数、设置页当前分区主标题等局部强调 | 只用于真实数据或当前任务标题，不用于装饰数字。     |

| 字重层级 | Token                      | 当前值 | 适用区域                         |
| -------- | -------------------------- | ------ | -------------------------------- |
| 标题     | `--font-weight-ui-title`   | `820`  | 页面标题、数据强调、重要分区标题 |
| 强标题   | `--font-weight-ui-strong`  | `750`  | 列表标题、表单标签、按钮         |
| 控件     | `--font-weight-ui-control` | `700`  | 导航项、筛选项、工具按钮         |
| 正文     | `--font-weight-ui-body`    | `500`  | 普通正文和说明                   |

## 当前设计债

| 问题                                                    | 影响                                        | 后续处理                                                             |
| ------------------------------------------------------- | ------------------------------------------- | -------------------------------------------------------------------- |
| `brand-ui-design.md` 的概念稿仍强调玻璃拟态和高对比卡片 | 容易让新增页面误以为所有区域都要卡片化      | 新页面优先遵守本文；品牌稿只作为首页 / 登录页参考。                  |
| 部分页面仍有裸色值和较大圆角                            | token 和圆角规则未完全收敛                  | 新增代码优先使用 `var(--color-*)`；存量按 touched surface 逐步收敛。 |
| 首页侧栏仍存在本地展示型热门话题 / 社区                 | 与生产真实数据策略不一致                    | 后续接入真实社区 / 排行数据前，生产路径应隐藏或降级。                |
| 存量 CSS 使用少量 `clamp(... vw ...)` 字号              | 与 CSS 规范“不要用 viewport 驱动字体”有偏差 | 新增页面不再扩大该模式；重构时改为固定层级 token。                   |

## 新增页面检查

| 检查项                  | 通过标准                                                                            |
| ----------------------- | ----------------------------------------------------------------------------------- |
| 页面是不是内容 / 工具页 | 是则优先平铺、分隔线和工作台布局，不默认 hero 卡片。                                |
| 页面是否使用真实数据    | 没有真实数据时展示 loading / error / empty / degraded，不伪造热度、成员数或未读数。 |
| 主色是否过量            | 青绿色只用于关键状态和动作；普通正文、边框、背景保持克制。                          |
| 卡片是否必要            | 只有独立 item、表单、侧栏面板、modal 或工具容器才使用卡片。                         |
| 移动端是否稳定          | 底部导航、主操作、列表标题和按钮文字不溢出、不跳动。                                |
